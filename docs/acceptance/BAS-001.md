## الهدف (Goal)

هل يستطيع **أول صاحب صالون** استخدام المنصة بالكامل بدون تدخل مطوّر؟

قصة الاستخدام (MVP):

```
صاحب صالون جديد
  → ينشئ حسابًا
  → يسجّل دخولًا
  → ينشئ الصالون (Tenant)
  → يرى أن salon module مفعّل تلقائيًا
  → يضيف أول خدمة
  → يضيف أول موظف
  → يضيف أول عميل
  → يعدّل الخدمة
  → يعدّل الموظف
  → يعدّل العميل
  → يسجّل خروجًا
  → يسجّل دخولًا من جديد
  → يجد كل البيانات كما تركها
```

---

## المتطلبات (Requirements)

1. App reachable at `SMOKE_BASE_URL` (default `http://127.0.0.1:3000`) against approved Staging.
2. Identity via `/api/v1/auth/signup` and `/api/v1/auth/login` only (no Admin/Service Role in-scenario).
3. Tenant bootstrap via `POST /api/v1/tenants`.
4. Salon module auto-enabled after tenant create.
5. First service / employee / customer: **create then update** (same entities kept for the story).
6. Logout = client discard of tokens (Bearer model).
7. Re-login shows the **same** entities with **updated** fields.
8. No privileged SQL, no Dashboard, no Service Role during BAS-001.

## Root cause proof (before Staging Auth change)

**Claim:** RB-004-01 is an **Environment / Operations** issue (Supabase Hosted Auth **Confirm email**), **not** an application, Architecture, Domain, RLS, or Public API contract bug.

**Differential evidence (same app binary, Public APIs only, no Service Role):**

| Probe | Request | HTTP | App / Auth message | Interpretation |
|-------|---------|------|--------------------|----------------|
| A | `POST /api/v1/auth/signup` | `400` | App `AUTH_ERROR`: *Sign up succeeded but no session was returned. Confirm email may be required.* | App correctly called Supabase `signUp`; GoTrue created the Identity but returned **no session** (Hosted Confirm email ON). |
| B | `POST /api/v1/auth/login` (same credentials, immediately after A) | `401` | App `UNAUTHENTICATED`: *Email not confirmed* | Verbatim Supabase Auth error — Identity exists; session refused until confirmation. |

**Ruled out:** app Zod/routing, Architecture JWT claims, Domain, RLS, API contract bug.

**Staging ops (not permanent Production policy):** [OP-003](../DECISION_LOG.md#op-003). After Confirm email OFF, re-run BAS-001 with a **fresh** identity.
