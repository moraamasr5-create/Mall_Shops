## 1. Canonical Rule (permanent · hierarchy over banners)

Authority flows from the **hierarchy**, not from whether a file carries a `LEGACY` banner.

### Restaurant (and future Modules by analogy)

If any document conflicts with, in order:

1. **MVP Thesis** (Product Constitution) — when ADOPTED for that Module  
2. **Knowledge Index** (Module entry map)  
3. **Canonical Contracts** (Index-canonical / Thesis-aligned)  
4. **Discovery** (Salon Locked → Module mapping)

…then that document is **Legacy automatically**, even if it has no Legacy banner and even if it lives under a “current” path.

### Forbidden uses of Legacy

No AI and no developer may use Legacy material to produce:

- Product Decisions  
- Exit Criteria  
- Contracts (as authoritative language)  
- Schema  
- APIs  
- UI Flows  

### Allowed uses of Legacy

Historical reading · anti-pattern study · forensic comparison — **only**.

### Banners

Legacy banners (e.g. on stub contract INDEX files) are **aids**, not the source of authority. Absence of a banner never rehabilitates a conflicting file.
