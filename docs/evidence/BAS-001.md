# BAS-001 — Salon Owner Happy Path

**Type:** Business Acceptance Scenario (not a Release Gate)  
**Parent Gate:** [RG-004 — RC1](../RELEASE_GATES.md#rg-004--rc1)  
**Purpose:** Prove that a **first salon owner** can start using the platform and **fully manage their salon** via APIs only — with **no manual DB or developer intervention**.

**Not:** Architecture Lock · ADR · new OP/RG · Feature scope.

---

## Why BAS-001 exists

`smoke:vs1` validates the minimum bootstrap path. RC1 requires more: a **data lifecycle** that mirrors how a real salon owner works — create several services, edit, delete, list, persist across sessions, and stay isolated from other tenants.

```
Isolated CRUD checks        →  insufficient for RC1
Data lifecycle (BAS-001)    →  required for RG-004
```

Any defect that **blocks this scenario** is a **Release Blocker** — fix before RG-005 / v1.0.0. It is **not** a Feature Request.

---

All tenant-scoped Salon requests require:

## Step-by-step (lifecycle)

Record `TOKEN`, `TENANT_ID`, and entity IDs as you go. Use a unique email per run.

### 1 — Signup

```bash
curl -s -X POST $BASE_URL/api/v1/auth/signup \
  -H "Content-Type: application/json" \
  -d '{"email":"bas001-owner@example.com","password":"SecurePass1!"}'
```

| Expect | Value |
|--------|-------|
| Status | `201` |
| Body | `data.accessToken`, `data.identity.id` |

### 2 — Create Tenant (first salon)

```bash
curl -s -X POST $BASE_URL/api/v1/tenants \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"صالون BAS-001"}'
```

| Expect | Value |
|--------|-------|
| Status | `201` |
| Body | `data.tenant.id`, `data.membership.role` = `OWNER` |

### 3 — Salon Enabled

```bash
curl -s $BASE_URL/api/v1/tenants/$TENANT_ID/modules \
  -H "Authorization: Bearer $TOKEN" \
  -H "X-Tenant-Id: $TENANT_ID"
```

| Expect |
|--------|
| Row with `moduleKey: "salon"` and `enabled: true` |

### 4 — Create 3 Services

Create three distinct services (names must differ). Save `SERVICE_A`, `SERVICE_B`, `SERVICE_C`.

```bash
# Service A — Haircut
curl -s -X POST $BASE_URL/api/v1/salon/services \
  -H "Authorization: Bearer $TOKEN" \
  -H "X-Tenant-Id: $TENANT_ID" \
  -H "Content-Type: application/json" \
  -d '{"name":"قص شعر","durationMin":30,"priceCents":5000,"currency":"SAR"}'

# Service B — Color
curl -s -X POST $BASE_URL/api/v1/salon/services \
  -H "Authorization: Bearer $TOKEN" \
  -H "X-Tenant-Id: $TENANT_ID" \
  -H "Content-Type: application/json" \
  -d '{"name":"صبغة","durationMin":90,"priceCents":15000,"currency":"SAR"}'

# Service C — Manicure
curl -s -X POST $BASE_URL/api/v1/salon/services \
  -H "Authorization: Bearer $TOKEN" \
  -H "X-Tenant-Id: $TENANT_ID" \
  -H "Content-Type: application/json" \
  -d '{"name":"مانيكير","durationMin":45,"priceCents":8000,"currency":"SAR"}'
```

**List check (owner “views catalogue”):**

```bash
curl -s $BASE_URL/api/v1/salon/services \
  -H "Authorization: Bearer $TOKEN" \
  -H "X-Tenant-Id: $TENANT_ID"
```

| Expect |
|--------|
| Status `200` |
| `data` length **≥ 3** |
| All three names present |

### 5 — Edit Service

Edit **Service B** (price + duration):

```bash
curl -s -X PATCH $BASE_URL/api/v1/salon/services/$SERVICE_B \
  -H "Authorization: Bearer $TOKEN" \
  -H "X-Tenant-Id: $TENANT_ID" \
  -H "Content-Type: application/json" \
  -d '{"priceCents":18000,"durationMin":120}'
```

| Expect |
|--------|
| Status `200` |
| `data.priceCents` = `18000`, `data.durationMin` = `120` |

Re-list services — Service B shows updated values; A and C unchanged.

### 6 — Delete Service

Delete **Service C** (soft-deactivate in VS1):

```bash
curl -s -X DELETE $BASE_URL/api/v1/salon/services/$SERVICE_C \
  -H "Authorization: Bearer $TOKEN" \
  -H "X-Tenant-Id: $TENANT_ID"
```

| Expect |
|--------|
| Status `200` |
| `data.active` = `false` |

### 7 — Verify delete does not break anything

**7a — List (active catalogue):**

```bash
curl -s $BASE_URL/api/v1/salon/services \
  -H "Authorization: Bearer $TOKEN" \
  -H "X-Tenant-Id: $TENANT_ID"
```

| Expect |
|--------|
| `data` length = **2** (A and B only) |
| Service C **not** in list |

**7b — Remaining services still readable:**

```bash
curl -s $BASE_URL/api/v1/salon/services/$SERVICE_A \
  -H "Authorization: Bearer $TOKEN" \
  -H "X-Tenant-Id: $TENANT_ID"
```

| Expect | Status `200`, service A intact |

**7c — Create still works after delete:**

```bash
curl -s -X POST $BASE_URL/api/v1/salon/services \
  -H "Authorization: Bearer $TOKEN" \
  -H "X-Tenant-Id: $TENANT_ID" \
  -H "Content-Type: application/json" \
  -d '{"name":"تسريحة","durationMin":60,"priceCents":12000,"currency":"SAR"}'
```

| Expect | Status `201` — proves delete did not corrupt tenant state |

### 8 — Create Employee

```bash
curl -s -X POST $BASE_URL/api/v1/salon/employees \
  -H "Authorization: Bearer $TOKEN" \
  -H "X-Tenant-Id: $TENANT_ID" \
  -H "Content-Type: application/json" \
  -d '{"name":"سارة","title":"مصففة شعر","phone":"0500000001"}'
```

Save `EMPLOYEE_ID`. List employees — count ≥ 1.

### 9 — Edit Employee

```bash
curl -s -X PATCH $BASE_URL/api/v1/salon/employees/$EMPLOYEE_ID \
  -H "Authorization: Bearer $TOKEN" \
  -H "X-Tenant-Id: $TENANT_ID" \
  -H "Content-Type: application/json" \
  -d '{"title":"مديرة الصالون","phone":"0500000099"}'
```

| Expect |
|--------|
| Status `200` |
| Updated `title` and `phone` in response |

### 10 — Create Customer

```bash
curl -s -X POST $BASE_URL/api/v1/salon/customers \
  -H "Authorization: Bearer $TOKEN" \
  -H "X-Tenant-Id: $TENANT_ID" \
  -H "Content-Type: application/json" \
  -d '{"name":"نورة","phone":"0500000002","notes":"عميلة دائمة"}'
```

Save `CUSTOMER_ID`. List customers — count ≥ 1.

### 11 — Login Again (new session)

```bash
curl -s -X POST $BASE_URL/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"bas001-owner@example.com","password":"SecurePass1!"}'
```

Use new `accessToken` as `TOKEN2`.

### 12 — Verify Persistence

```bash
# Tenant still visible
curl -s $BASE_URL/api/v1/tenants \
  -H "Authorization: Bearer $TOKEN2"

# Services: 3 active (A, B, new "تسريحة"; C deleted)
curl -s $BASE_URL/api/v1/salon/services \
  -H "Authorization: Bearer $TOKEN2" \
  -H "X-Tenant-Id: $TENANT_ID"

# Employee edit persisted
curl -s $BASE_URL/api/v1/salon/employees/$EMPLOYEE_ID \
  -H "Authorization: Bearer $TOKEN2" \
  -H "X-Tenant-Id: $TENANT_ID"

# Customer persisted
curl -s $BASE_URL/api/v1/salon/customers/$CUSTOMER_ID \
  -H "Authorization: Bearer $TOKEN2" \
  -H "X-Tenant-Id: $TENANT_ID"
```

| Expect |
|--------|
| Tenant in list |
| Services list = 3 active; edited B has `priceCents: 18000` |
| Employee `title` = `مديرة الصالون` |
| Customer `name` = `نورة` |

### 13 — Cross-Tenant (isolation)

**13a — Automated (required):**

```bash
npm run evidence:cross-tenant
```

| Expect | `docs/evidence/cross-tenant-latest.md` → **Overall: PASS** |

**13b — Spot check (recommended during BAS-001):**

1. Complete steps 1–2 again with a **second** identity (`bas001-other@example.com`) → `TENANT_B`.
2. With Tenant B token + `X-Tenant-Id: $TENANT_B`, request Tenant A service by ID:

```bash
curl -s $BASE_URL/api/v1/salon/services/$SERVICE_A \
  -H "Authorization: Bearer $TOKEN_B" \
  -H "X-Tenant-Id: $TENANT_B"
```

| Expect | `404` or empty — **no** Tenant A data |

3. With Tenant A token, set `X-Tenant-Id: $TENANT_B` (mismatched header):

| Expect | `403` — `X-Tenant-Id must match path tenantId` or permission denied |

## PASS criteria (RG-004)

BAS-001 = **PASS** when **all** are true:

| # | Criterion |
|---|-----------|
| 1 | Full scenario steps 1–13 complete without manual DB edits |
| 2 | 3 services created; edit + delete lifecycle behaves as documented |
| 3 | Delete removes service from **list** but does not break create/read for others |
| 4 | Employee + customer created and edited |
| 5 | Re-login shows all persisted data |
| 6 | Cross-tenant evidence **Overall: PASS** |
| 7 | `npm run verify` + CI green on RC1 commit |
| 8 | **Zero** open Release Blockers from this scenario |

Record outcome in [`bas-001-latest.md`](./bas-001-latest.md).

## FAIL criteria

| Category | Examples |
|----------|----------|
| **Lifecycle broken** | Cannot create 3 services; edit/delete fails; list wrong count after delete |
| **Persistence broken** | Data missing after re-login |
| **Isolation broken** | Cross-tenant read/write succeeds |
| **Environment** | `check:env` FAIL; migrations not applied |
| **Code gate** | `verify` or CI red |

**Environment unavailable** (Docker down, missing `.env`) = **NOT_EXECUTED** — fix environment and re-run; not a product FAIL.
